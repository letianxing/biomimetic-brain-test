现场注册与验收详细步骤
先按“Mac全系统启动与三项验收.txt”启动系统。默认SESSION_ID=mac-conversation-test。

一、直接说话注册（无需网页或终端操作）

一键启动完成、摄像头和麦克风开始采集后，注册者一人面对摄像头说：

“你好小圆，我叫小天，请记住我，我是你的主人。”

将“小天”换成自己的称呼。自然说完整句话，至少2秒；等待机器人口头回复：
“记住啦，小天，你是我的主人了。”

注册普通熟人则说：
“你好小圆，我叫小明，请记住我。”

成功会回复“记住啦，小明，你是我的朋友了。”
不需要打开、点击任何网页；8092仅用于观察和排查。
多人入镜、重叠说话或样本无效时，会口头提示，请单独面对镜头再完整说一次。
已经识别的主人再次说注册话术，会回复“你已经是主人啦，不要来挑逗我了。”，不会重复注册。
熟人会回复“我已经认识你啦，不用再注册了。”
注意：机器人必须识别出名字和明确的“请记住我”请求；普通聊天中的自我介绍不会自动写入身份档案。
注册角色是这台本地测试机器的交互身份标签，不是安全身份认证。
以下测试中的person1/person2可替换为注册时使用的“小天/小明”。

二、测试1：多人聊天、注意力门控与打断

A. 旁人聊天应保持安静
两人看着彼此，不看机器人，不用“小圆”等定向称呼，轮流说，句间留约1秒：
person1：“周六我想去紫竹院公园。”
person2：“那就下午三点，在东门见。”
预期：两句均出现在8094 heard和HRI里；person_id对应；attention.addressed_to_robot=false；机器人不插话。
主人刚注册出现时可能单独触发一次主动问候；等问候结束再开始此项，或者先保持主人在场。

B. 转向机器人询问
一人看向机器人，说：“小圆，请告诉我刚才我们约在哪里、几点见面。”
预期：本句 attention.listen=true、addressed_to_robot=true；回复引用刚才的公园、下午三点和东门，不把两人的话混淆。
不要只说“你好”测试Qwen，因为它属于快脑固定回复。

C. 有效打断
面对机器人说：“小圆，请详细讲一个关于森林的小故事。”
等扬声器开始说话，面向机器人说：“小圆，等一下，先告诉我刚才约定的时间。”
预期：8092 interruption_candidate 有通过的attention，来源为流式ASR或注视+唇动+声音活动；8094 s2s.interruptions 增加；旧声音停止；用户说完后回复新问题；旧回复不会后来又冒出来。
生成过程中也可做同样测试，旧LLM结果应丢弃。
120ms只是注意力连续确认窗；总延迟还包含VAD、ASR、网络和声学处理，应现场计时。

D. 无效插话不能打断
机器人讲故事时，person2转向person1说：“你等一下，我拿个杯子。”不要看机器人，不叫机器人。
预期：机器人继续说；该句被记录为非机器人对话；不能只因出现“等一下/停止”就打断。
再试旁人说“他说机器人很有趣”，不应仅凭句中提到机器人而唤醒。

E. 自回声与重叠压力测试
让机器人连续回答几次，自己保持安静；不能把机器人外放内容作为用户的新句子反复回答。
之后增加两人重叠说话、较远距离和不同音量，记录错字、漏句、错人、误打断次数。这是准确率压力项，不应以理想场景一次成功判定全通过。

三、测试2：记忆质量、身份、持久化

查询记忆（终端三）：

curl --noproxy '*' -s http://127.0.0.1:8788/v1/search \
  -H 'Content-Type: application/json' \
  -d '{"scope":{"subject_id":"local-user","robot_id":"reachy-mini","session_id":"mac-conversation-test"},"kind":"heard_utterance","limit":30}' \
  | python3 -m json.tool

返回在 hits[].record，不是 results。
逐句检查：
- text：识别文字是否正确；
- entity.person_id：是否对应person1/person2；
- structured.attention.addressed_to_robot：对机器人或旁人；
- structured.identity_source / identity_confidence：归属依据，未知不能冒充确定；
- structured.transcript.started_ms / ended_ms：时间；
- structured.visible_participants：只代表可见候选；
- trace_id：相同一句重试不能重复产生多条同内容事件。

只查 person1：

curl --noproxy '*' -s http://127.0.0.1:8788/v1/search \
  -H 'Content-Type: application/json' \
  -d '{"scope":{"subject_id":"local-user","robot_id":"reachy-mini","session_id":"mac-conversation-test"},"kind":"heard_utterance","entity_id":"person1","limit":30}' \
  | python3 -m json.tool

继续分别问：“小圆，刚才person1想去哪里？”、“小圆，谁提议下午三点？”
回复应基于实际记录；错字应先定位Voice；错人先定位声纹/视听关联；HRI有记录但回答错才进一步看检索与Qwen。

持久化：按“Mac全系统启动与三项验收.txt”停止并重启，保持完全相同 SESSION_ID。再次查询，原记忆仍应存在。
HRI文件：~/Golands/hri-memory-service/data/events.jsonl
Brain待发送队列：~/Golands/biomimetic-brain-test/data/outbox.sqlite3
memory.pending>0 或 memory.error 非空表示尚未确认写入HRI；不要当作记忆验收成功。
更换 SESSION_ID 会新建记录会话，Brain仍可检索同一用户空间与机器人的旧会话。Brain会跨同一subject_id和robot_id的会话检索历史；历史面板仍按选定会话查询。

四、测试3：主人出现、情绪与主动搭话

先由person1说：“我想周六去紫竹院公园，刚才还没决定几点出发。”确认这句已按person1写入记忆。
距离上次问候至少30秒，再让person1完全离开摄像头至少5秒。其他人保持安静。
person1重新出现并面对摄像头，不需要先说话。
预期：视觉确认 role=owner、身份置信度通过，注意力连续锁定主人且锁定后环境持续安静约5秒后，Brain基于Qwen主动搭话。
可能类似：“你回来啦，还想继续聊周六去公园的计划吗？”措辞由模型决定，不要求逐字一致。
8094 events：path=proactive、reason=owner_return_llm、memory_count>0，trigger含真实情绪线索。
持续坐在镜头前一分钟，不应每30秒再问候一次。
换person2进来，不应冒充主人触发相同问候。
主人表情变化只作为不确定视觉线索，不把某个表情标签当成确定心理状态。
主人主动问候同样可用测试1的C的方式打断。


音乐与快反射：普通讲话不应识别为音乐；播放已知曲目检查genre/BPM，静音后状态清除；拍手检查惊跳不重复触发；阵列后方说话检查方向和定向事件。


五、8092实时总览与可回溯检查

页面上方直接选择摄像头/麦克风，点击对应“切换”按钮；另一类采集不重启。
观察实时画面、视觉情绪有效性/手势、流式ASR、最终句、原始VAD和当前注意力。
“本次回复对应的输入”绑定具体utterance_id，不是随时覆盖成最新ASR。
TTS区显示生成中的回复、当前播放分句、首文本/首段/播放耗时；可调语速。
“历史ASR / 对话记忆”按会话、person、关键词查询与翻页；“回溯这轮”查看门控、生成、播放、打断时间线。
“本次送入模型的记忆”展示此次回复实际引用的输入上下文，方便比对回答。
回声单独选择“被排除的自身回声”查看；新检测到的回声不会当用户记忆或再次触发回复。
旧记录不会删除；召回时只排除有明确回声标签或同时段播放证据的高匹配片段，不能保证修复全部旧错记。
记录保存识别内容、感知证据和事件时间；没有连续录制原始视频/音频，不能当音视频录像回放。

六、惊跳、注意力与空间来源

环境安静时制造一次适度突发声音，观察声音startle事件 → 8092反射注意力 → Brain短叹“哎呀！”。
同一事件不重复惊叹，连续惊跳短叹有8秒冷却；注意力约保持1.8秒。
视觉惊跳使用固定人脸框面积的显著快速增长；支持YOLO已识别物体在中心大面积突然出现并连续确认。初始场景不触发；不是通用危险物体检测。
惊跳仅唤起定向注意力，不自动认定某人在和机器人说话，不绕过正常对话门控。
Mac内置单麦克风：没有可靠方位，显示未知；MicArray：可提供方位角，不等于距离或3D点。
RGB人脸大小估算的距离不是实测3D。只有有效position_xyz_m和frame_id才标记3D。
未来接入深度相机/3D声源时，需要统一坐标标定和时间；不同frame_id不能直接融合坐标。
本Mac测试执行短叹和注意力状态，不驱动实体机器人头部转动。

七、实时性检查

默认Sherpa常驻流式解码；Brain消费ROS2注意力流，ROS2不可用时回退HTTP并标注。
千问文本流按短句交给TTS，后一段生成与前一段播放重叠；macOS say仍按分句合成，不是逐音素流式TTS。
播放设备预热复用，打断会清空旧分句并取消旧生成。模型耗时在8092显示实测值。
本机曾测得：ASR相同音频冷启动约1973ms、常驻约247ms；视觉约18.8fps；单独Qwen首文本约360ms。
这些是样本测量，不是整条链路的保证；满负载、音频窗口和句末检测都会增加延迟。
音乐类型/BPM需要数秒音频窗口，实时刷新不代表瞬间即可可靠识别。
先做轮流说话，再测试重叠；单路ASR不能保证同时重叠的每个人都逐字正确，应统计漏句与错人。


视觉修正（2026-09-15）
FER+输入已恢复0–255像素尺度，低置信度或类别接近时emotion_valid=false。
唇动改为MediaPipe Face Landmarker嘴唇关键点的几何变化，移除嘴部明暗/像素差规则。
8092显示lip_motion_valid=false时为“未知/待确认”；新跟踪、关键点失败或大角度侧脸不作为唇动证据。
现场验证：先闭嘴轻微移动头部，再静止开口，再自然说话；比较VAD、唇动和打断是否一致。咀嚼、微笑也可能产生真实嘴部运动，不能仅凭唇动认定讲话。
离线样本新增关键点模型推理中位数约9.5ms，不代表多人场景的整帧耗时保证。

陌生人记忆与身份去重（2026-09-15）
干净、非回声、非重叠且足够长的语音有有效声纹后，自动建立stranger_编号；再次识别到同一声纹复用编号。未知或不可靠声纹仍保留unknown，不强行猜人。
每句话单独保存ASR、Person ID、对话门控和证据；稳定声纹档案不按发言重复入库。正式注册关联原陌生编号，检索保留这段历史。
明确对话时，当前问题、该人/旧编号相关记忆、环境对话记忆及视听身份线索一起交给千问。
旁人讲话与最终ASR均延后主动问候，安静至少5秒后才允许主人出现问候。
声音惊跳初始门槛为-12 dBFS及24 dB相对突增，预热2.5秒、冷却8秒；dBFS不是校准声压，实际麦克风音量仍需现场验证。
新增身份写入使用稳定档案标识去重；之前已存在的历史记录不删除。

主动搭话与接话的优先级（本轮更新）
主人身份确认还不够：必须注意力目标锁定主人、置信度至少0.62、锁定后连续等待5秒且期间周围安静，才考虑主动问候。
注意力转移或变旧时取消主动生成/播放；尚未播出的问候遇到新鲜语音活动或partial也会取消。
主人和别人聊到一半，转过来说“你说是吧？”：这是直接提问，当前问题+最近两分钟最多8条对话+个人/环境历史记忆共同送给千问。不能机械附和，不能切成问候。
这个问题回答后，本次在场期间视为已经交谈，不再补发进入问候；离开后再次出现才重新评估。
注册增加连续同脸采样与唇动证据、两段声纹一致性预检；两种模态都预检通过后才写档案。
身份不一致时使用可靠声纹作为说话人，保留identity_conflict/visual_person_id，不把冲突人脸绑定过去。

主动搭话等待规则：从注意力锁定主人时开始计时，默认连续安静5秒才开口。主人或旁人开口后重新等待；注意力转移/身份无法确认时重置锁定计时。此前已经对话的主人仍不重复问候。可通过BRAIN_PROACTIVE_WAIT_MS调整默认等待值。

静默注视聚焦：无其他目标、无新鲜语音活动时，已识别主人持续正面注视约800ms，建立独立视觉注意力（visual_owner_focus）。此时listen=true表示准备交流，addressed_to_robot=false表示尚无对机器人发言；继续安静5秒才评估主动搭话。Person融合保留已确认owner角色。

最新分级淡出、VAP、声学特征和目标保持参数以同目录“仿生打断与注意力保持更新.txt”为准；旧的立即释放/统一打断时间参数已被替换。
